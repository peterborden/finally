  <behavior>
    Each scenario asserts an observable user-facing outcome (prefer role/text/placeholder/aria-label selectors that already exist; add a minimal data-testid to a component ONLY if no stable selector exists, treating that as a behavior-neutral test hook). All under LLM_MOCK=true against baseURL:
    - Fresh start: the 10 default tickers (AAPL, GOOGL, MSFT, AMZN, TSLA, NVDA, META, JPM, V, NFLX) appear in the watchlist; the header shows a $10,000 cash balance; at least one price updates within a few seconds (streaming), proven by polling a ticker's rendered price changing OR the connection dot reaching connected.
    - Add ticker: type a new symbol (e.g. PYPL) into the add-ticker input, submit, assert the row appears; then remove it and assert it disappears.
    - Buy shares: enter ticker + quantity in the trade bar, click Buy, assert cash decreases and a position row for that ticker appears in the positions table.
    - Sell shares: with an existing position, sell some/all, assert cash increases and the position quantity decreases or the row disappears.
    - Portfolio visualizations render: after holding a position, assert the heatmap/treemap and the P&L chart are present in the DOM (container/svg present).
    - AI chat (mocked): expand the chat panel, send a message containing a mock directive (e.g. "buy some [[buy:AAPL:2]]"), assert a response bubble appears and the executed trade shows inline (mock reply text and/or an inline trade/position confirmation), and the portfolio reflects the new/updated AAPL position.
    - SSE reconnect resilience: after prices are flowing, simulate a transient disconnect (e.g. go offline via context then back online, or reload the page) and assert the stream resumes (connection dot returns to connected and prices update again).
    Use robust waits (expect.poll / web-first assertions), never fixed long sleeps, and keep every assertion deterministic given LLM_MOCK.
  </behavior>
