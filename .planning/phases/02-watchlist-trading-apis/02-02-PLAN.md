    - .planning/phases/02-watchlist-trading-apis/02-CONTEXT.md — the "Trade execution semantics" block is authoritative for the buy/sell formulas and rejection rules.
    - .planning/codebase/CONVENTIONS.md and backend/app/market/models.py — follow the frozen-dataclass style (`from __future__ import annotations`, `slots=True`, full type hints) already used in the market subsystem.
  </read_first>
  <behavior>
    Model the current position as (quantity, avg_cost) and the request as (side, quantity, price). apply_trade returns either a success result carrying the new cash, new position quantity, new avg_cost, a remove_position flag, and the filled price/quantity — or a typed rejection with a clear message. It never mutates its inputs.
    - Buy with sufficient cash: new_cash = cash - qty*price; new_qty = old_qty + qty; new_avg = (old_qty*old_avg + qty*price)/(old_qty+qty). Fresh position (old_qty 0) -> new_avg == price.
    - Buy into an existing position: average cost is the weighted blend (e.g. 10 @ 100 then 10 @ 200 -> 20 @ 150).
    - Buy fractional (e.g. 2.5 shares) computes exact cash and avg_cost.
    - Buy with cash < qty*price: rejected, message names the shortfall, no numbers returned as if applied.
    - Sell with position qty >= requested: new_cash = cash + qty*price; new_qty = old_qty - qty; avg_cost unchanged.
    - Sell entire position (or leaving |remaining| <= a small epsilon such as 1e-9): remove_position flag is True.
    - Sell fractional leaving a partial position keeps remove_position False and preserves avg_cost.
    - Sell with no position or position qty < requested: rejected with a clear message, no state returned as if applied.
    - Zero or negative quantity, and non-positive price, are rejected as invalid.
  </behavior>
  <action>
    Write the RED tests first in backend/tests/test_trade_engine.py enumerating every case in the behavior block (use pytest.approx for float comparisons), run them to confirm they fail, then implement backend/app/trade_engine.py to make them pass.

    Design (Claude's discretion on exact names, keep it pure — no imports of sqlite3, fastapi, or app.market):
    - A Side enum or Literal["buy","sell"].
    - An immutable input describing the current position (quantity: float, avg_cost: float) — a fresh/empty position is quantity 0.0.
    - A TradeResult dataclass with new_cash, new_quantity, new_avg_cost, remove_position: bool, filled_quantity, filled_price.
    - apply_trade(side, quantity, price, cash, position) returning TradeResult, and raising a dedicated TradeError (or returning a rejection object — pick one and be consistent) with a human-readable message for the insufficient-cash, insufficient-shares, and invalid-input cases. The endpoint in plan 02-03 will translate that into an HTTP 400.
    - Use an epsilon constant for the sell-to-zero removal test so floating-point residue does not leave a dust position.

    Do not perform any rounding of monetary values beyond what the formulas produce; the caller decides display formatting.
