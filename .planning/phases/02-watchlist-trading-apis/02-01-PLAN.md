  <action>
    Create backend/app/watchlist.py exposing create_watchlist_router() -> APIRouter (factory pattern, no module-level globals, matching create_stream_router). Follow project conventions: `from __future__ import annotations`, full type hints, `str | None`, module docstring, module logger. Use Pydantic models for request/response validation.

    Define Pydantic models: WatchlistAddRequest with a single field `ticker: str`; WatchlistEntry response model with fields ticker: str, price: float | None, previous_price: float | None, change: float | None, change_percent: float | None, direction: str | None, added_at: str | None. Normalize every inbound ticker to upper-case and strip whitespace via a validator so "aapl " and "AAPL" collide on the UNIQUE(user_id, ticker) constraint.

    Endpoints (all use the "default" user_id constant; obtain the DB connection with get_connection(get_db_path()) and close it in a finally block; obtain cache/source via the Request object as request.app.state.price_cache and request.app.state.market_source):

    - GET /api/watchlist (WATCH-01): SELECT ticker, added_at FROM watchlist WHERE user_id = ? ORDER BY added_at, then for each row read the cache via price_cache.get(ticker) and build a WatchlistEntry. When the cache has no entry yet, return the price/change fields as null rather than raising. Return list[WatchlistEntry].

    - POST /api/watchlist (WATCH-02): validate the body, INSERT OR IGNORE INTO watchlist (id=uuid4().hex, user_id, ticker, added_at=UTC isoformat) so re-adding is a safe no-op, commit, then await request.app.state.market_source.add_ticker(ticker) when market_source is not None (guard for the Phase-1 case where the source failed to start — log a warning and still return the DB row). Return the resulting WatchlistEntry (read the row back plus current cache price). Use status_code 201.

    - DELETE /api/watchlist/{ticker} (WATCH-03): normalize the path ticker, DELETE FROM watchlist WHERE user_id = ? AND ticker = ?, commit, then await request.app.state.market_source.remove_ticker(ticker) when market_source is not None. Idempotent: return 200 with a small confirmation body ({"ticker": ..., "removed": bool}) whether or not a row existed. Do not 404 on an absent ticker.

    Use parameterized SQL for every query (no string interpolation of ticker or user_id) — the ticker is untrusted client input.
