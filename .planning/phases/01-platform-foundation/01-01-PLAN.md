<objective>
Build the standalone SQLite persistence layer for FinAlly: the six-table schema (per PLAN.md §7), an env-driven connection helper, default seed data, and an idempotent lazy-initialization function. This plan produces NO HTTP surface — it is the pure data engine that Plan 01-02 wires into the FastAPI app's "create on first request" middleware.

Purpose: Satisfies DB-01 (lazy create/seed engine), DB-02 (six-table schema with user_id), DB-03 (default $10k profile + 10-ticker watchlist). Uses stdlib `sqlite3` only — no ORM, no new runtime dependency — matching the "no DB server, zero-config" ethos.
Output: `backend/app/db/` package (schema.py, connection.py, seed.py, __init__.py) exporting `init_database`, `get_connection`, `get_db_path`; plus a pytest suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → filesystem | FINALLY_DB_PATH controls where the SQLite file is created |
| caller values → SQL | seed data written into SQLite |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-DB-01 | Tampering | seed.py / init_database SQL | low | mitigate | All inserts use parameterized queries; no user-supplied input reaches SQL in Phase 1 (seed values are constants) |
| T-01-DB-02 | Information Disclosure / Tampering | connection.get_db_path (FINALLY_DB_PATH) | low | accept | Single-user local app; path is operator-controlled. Default stays inside project db/. Parent dir created with mkdir(exist_ok=True); no traversal from untrusted input |
| T-01-DB-03 | Denial of Service | repeated init_database calls | low | mitigate | CREATE TABLE IF NOT EXISTS + INSERT OR IGNORE make re-init a cheap no-op; no unbounded growth |

No package-manager installs in this plan (stdlib sqlite3 only) — no T-01-SC applies here.
</threat_model>
